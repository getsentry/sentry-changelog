Your agent now picks a dedicated search tool for each kind of data, can check whether Sentry dropped events before trusting a chart, and can remove stale cron monitor environments.

These updates shipped to the hosted Sentry MCP server at [mcp.sentry.dev](https://mcp.sentry.dev) between October 1 and October 12, 2026.

## Dataset-specific search tools

`search_events` is replaced by `search_errors`, `search_logs`, `search_traces`, `search_metrics`, `search_profiles`, and `search_replays`. Each tool searches exactly one dataset, so a log search can no longer come back with spans. `search_events` still works through `execute_sentry_tool` as a deprecated alias. With [Shaun Kaasten](https://github.com/skaasten) in [#1374](https://linear.review/getsentry/toolkit/pull/1374).

Time series results now mark buckets that are still receiving data with `*`, leave them out of the peak, and label the total "(so far)". When Sentry reports it, an **Ingestion** line shows how far behind the data is, so a trailing dip isn't mistaken for a real drop. By [edwardgou-sentry](https://github.com/edwardgou-sentry) in [#1441](https://linear.review/getsentry/toolkit/pull/1441).

## See which events were dropped

`find_dropped_events` shows what Sentry received but didn't store for spans, logs, metrics, or errors, broken down over time by outcome (such as rate limited, filtered, invalid, or client-side sampling) and reason, alongside the accepted volume. Your agent can use it to explain a flat chart or missing data. It's part of the default **Inspect Issues & Events** skill. By [Saraj Singh Manes](https://github.com/manessaraj) in [#1410](https://linear.review/getsentry/toolkit/pull/1410).

## Delete cron monitor environments

`delete_monitor_environment` removes one environment from a cron monitor and keeps the monitor and its other environments. It requires the **Manage Projects & Teams** skill and is available through `search_sentry_tools` and `execute_sentry_tool`. By [Evan Purkhiser](https://github.com/evanpurkhiser) in [#1443](https://linear.review/getsentry/toolkit/pull/1443).

## Fixes and setup

- `get_issue_details` no longer fails on older events whose extra context is empty. By [Miguel Betegón](https://github.com/betegon) in [#1353](https://linear.review/getsentry/toolkit/pull/1353).
- mcp.sentry.dev now has setup instructions for the [Pi](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/mcp.md) coding agent, for both the hosted and stdio servers. By [Ramiz Wachtler](https://github.com/rwachtler) in [#1397](https://linear.review/getsentry/toolkit/pull/1397).

## Are you using the stdio MCP server?

There was no new [`@sentry/mcp-server`](https://www.npmjs.com/package/@sentry/mcp-server) release in this period. The latest version is still [0.42.0](https://github.com/getsentry/toolkit/releases/tag/0.42.0), so these changes are only on mcp.sentry.dev until the next npm release.
